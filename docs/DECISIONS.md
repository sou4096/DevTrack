# 設計判断

## 2026-11-08: ローカル優先

SQLiteを各端末の記録の正本とする。オフラインでの記録と復旧を可能にし、送信キューと変更を同一トランザクションで保存する。同期プロトコルの詳細と競合解決はPhase 3で実装・検証する。

## 2026-11-08: 基盤検証は標準ライブラリを使用

アプリの依存関係が未確定のため、Phase 0の文書・構成チェックにPython標準ライブラリを使用する。各アプリのビルドと機能テストの代替にはしない。

## 未決定

最低OSバージョン、SQLiteラッパー、同期の具体的な競合解決、OAuthリダイレクトの方式、削除・保持ポリシー、各IDE・OSの検出能力は公式仕様と実機検証に基づき決定する。

## 2026-11-08: Firebaseの初期アクセス制御

未設計のコレクションはすべて拒否し、`users/{uid}` のプロフィールのみ所有者に許可する。必須・許可フィールド、型、作成日時の不変性、連続バージョンを検証し、物理削除とリストを拒否する。データ同期用ルールはPhase 3でモデルとともに追加する。クライアント時刻は信頼された監査時刻ではない。

Firebase JavaScript SDKが固定する古い `@grpc/grpc-js` に高深刻度の脆弱性が報告されているため、検証用依存関係では1.14.7に上書きし、エミュレータテストを実行する。SDKが修正された際は上書きを再評価する。残るnpm監査の中程度の指摘は主にFirebase CLIの開発用依存であり、更新を追跡する。
