# 確定仕様

## 対象と操作

iOSはホーム、プロジェクト、履歴、分析の4タブ。手動タイマーの開始・一時停止・再開・終了、プロジェクト・カテゴリの切替、履歴の追加・編集・削除を提供する。計測状態は復元可能とし、切替時は時間区間を分割する。PCはmacOSのメニューバーとWindowsのトレイに常駐し、対象の前面アプリと操作状態を用いて計測する。IDEの起動だけでは計測しない。

プロジェクト判定は拡張機能、登録フォルダ、前面ウィンドウ、シェル連携、許可済みサイトを利用する。高信頼は自動確定、中信頼は候補提示、低信頼は未分類とする。絶対パスは原則端末内に留める。ブラウザの本文、キー入力、全閲覧履歴は収集しない。

## 時間と集計

WorkSessionは操作の単位、TimeIntervalは計上可能な区間とする。UTCで保存し、表示・日別集計はタイムゾーンを適用する。放置判定は最終操作から5分、最初の2分は暫定作業時間、残りは除外して確認可能にする。保留中の除外時間は確定済み時間へ無条件に加算しない。ロック・スリープ中は加算しない。

重複区間は集計時に取り扱い、元記録は保持する。手動記録を自動記録より優先し、自動記録間の判定が不明な場合は確認待ちとする。編集や競合解決後に再計算する。

## 同期とアカウント

各端末で先にSQLiteへ保存し、変更と同期待ち操作を原子的に記録する。UUIDで対象と操作を識別し、再送は冪等とする。更新にはバージョン検証を行い、競合する変更は破棄せず保持する。削除は論理削除を基本とする。データはFirebase UID単位で分離し、ログアウト・別アカウントへの切替でも混在させない。Firestore SDKのキャッシュと独自同期の責任境界を実装前に検証する。

主要モデル: User、Project、Category、Device、WorkSession、TimeInterval、IdleReview、Goal、SyncConflict、SyncOperation。同期対象には必要に応じてUUID、作成・更新時刻、バージョン、端末ID、論理削除、同期状態を持たせる。DBスキーマはマイグレーションで変更する。

認証はメール・パスワードとGoogleログイン。PCはOAuth 2.0とPKCE、OSの安全な資格情報保管領域を用いる。Firebase Admin SDKの秘密鍵をクライアントに含めない。アカウント削除の設計、認証方式の安全な関連付け、エミュレータによるアクセス制御検証を行う。

## 拡張と制約

iOSはホーム・ロック画面ウィジェット、Live Activities、対応機種のDynamic Island、CSV・JSON出力を予定。Live Activityの終了と作業セッションの終了は分離する。外観は初期状態でシステムに従い、VoiceOverとDynamic Typeを考慮する。

具体的なOS対応バージョン、判定根拠と信頼度の境界、競合解決UI、アカウント削除の詳細は実装時に決定・記録する。
