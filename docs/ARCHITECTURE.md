# アーキテクチャ

## 責任の分離

- iOS: SwiftUI、SQLite、Firebase認証、ウィジェット等。SQLiteを記録の正本とする。
- PC: Tauri 2とRust、SQLite、OS状態検出、各OSの資格情報保管。
- クラウド: Firebase AuthenticationとFirestore。アクセスは認証されたユーザー権限で行う。
- 将来の連携: IDE・シェル・ブラウザから最小限の情報を取得し、ローカルでプロジェクト候補を判定する。

## データの流れ

iOS・PCの終了済み履歴は、SQLiteの変更と送信待ちを同じトランザクションで保存する。Firestoreでは本人の `history` の版と不変の `historyOps` を同時に更新し、操作IDで再送を判定する。変更の前提となる版が異なる場合は上書きせず競合として表示する。選ばなかった変更は端末内に保管する。Firestoreの永続キャッシュは使わず、送信待ちと受信位置はSQLiteが管理する。通常は最近の変更を重複取得し、少なくともアプリ使用中に日次で全体を再照合する。バックグラウンドでの定期実行は保証しない。

現在の同期対象は終了済みの作業区間に限る。プロジェクト・カテゴリそのものの変更、計測中の状態、競合解決で選ばなかった変更の他端末への保管、異なる作業間の重複調整と集計は未実装。PCで新規記録に指定するプロジェクト・カテゴリ名は、同期済みの履歴に一意な同名項目があれば再利用する。プロジェクトやカテゴリ自体の同期とは別の仕組みであり、同名項目が複数あれば新規記録での自動選択を行わない。

## 境界

SQLiteはFirebase UIDごとに分離し、Firestore Rulesは本人以外の履歴アクセスと削除要求中のアクセスを拒否する。アカウントID・絶対パス・認証情報をログへ不用意に出力しない。PCの資格情報保管、ローカル連携の認証、全端末へのアカウント削除の伝播は未完成。

## ディレクトリ

`docs/` は仕様と判断、`tests/` と `scripts/` は基盤検証、`.github/workflows/` はCI。アプリ・連携のディレクトリは各フェーズで実際の構成に合わせて追加する。
